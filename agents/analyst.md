# Analyst：从素材库写出 `briefs/<slug>.py`

你拿到：产品信息（名字、图片 / 链接、用户说过的话）、工作区 `$WS`（里面已经建好 `data/library-jg/`）。所有命令写 `python3 $WS/scripts/…`。
你交出：`briefs/<slug>.py`（所有判断都在这里），`python3 scripts/atlas_build.py <slug>` 能跑通，控制台数字和你写的结论一致。
字段契约见 `$WS/guide/references/brief-config.md`，完整实例见 `$WS/guide/references/example-brief.py`（橘子肉肉）。**从实例复制结构再改**，不要从零写；实例里的笔记 id 在新素材库里都不存在，全部换掉。

工具：`probe.py`（lib / group / laws / note）、`sheet.py`（封面对照图）、`frames.py`（视频抽帧 / 图集拼图）、引擎本身。
**先写草稿**：只有 PRODUCT / CUT / SOURCE / CLUSTERS 时，`atlas_build.py <slug>` 只打印候选池（相关性、爆品度、✓ 入选、◆ 右上角），用它反复调圈组和打分；之后再写 COMPETITORS / SELECTION / TEARDOWNS / LAWS。

## 1. 产品（`PRODUCT`）

名字、品牌、一句话、品类、价格、人群、平台、本轮目标、3 个卖点、`copy.transferDef`（对这个产品来说「好抄」是什么意思）。
用户没给的照写推断，**开头写「待确认：」或末尾写「（推断）」**，页面会如实显示。产品图上能读到的字（规格、产地、卖点文案）都用上。

## 2. 圈候选池（`CLUSTERS`，8–10 组，入选 3 组）

先 `probe.py lib` 看抓到了哪些榜单，再用 `probe.py group "<regex>" --title` 一组一组试：

1. **直接同类**一定要有一组（同品类同原料），哪怕不火。不火就是结论：「还没人做火 = 空位」，落选标签用「还不够火」。
2. 再按「抢同一批人、讲同一个故事」圈：同货架的邻近品类、同一个使用时刻（解馋、通勤、送礼…）、跨界新玩家、渠道清单、价格钩子、健康承诺、人群（孕期 / 儿童）。
3. **只匹配标题**（`T(i)`），除非是按品牌号圈（`TS(i)` 含账号名）。账号名里满是「橘子」「果干」，粉丝昵称、剧集角色名也会撞词：写一个 `NOISE` 正则先排掉。
4. 每组看 top 笔记标题，**再用 `sheet.py --match` 看封面**：标题常常不写品牌，封面写。
5. 一条笔记只属于一组：后面的组 `exclude` 前面所有组（顺序 = 优先级，越具体越靠前）。
6. 三个判断分（0–100）人群 / 动机 / 动作，相关性 = 0.3·人群 + 0.4·动机 + 0.3·动作。**打分要诚实**：分界线 70 / 50，`picked` 必须恰好是右上角那几组；落在右上角却不想选，说明分打高了，改分并在 `why` 里讲清楚。
7. 落选标签用：动作对不上 / 样本太少 / 动机不对 / 人群不对 / 账号太集中 / 只做单一输出 / 还不够火。
8. `SELECTION.common` 写入选组的 3 条共性，可用 `{picked_notes}` `{picked_accts}` 占位。

> 个位数笔记的组再像也别选。10 条左右但爆款率很高的（如新品上新）可以选。

## 3. 拆形式（`COMPETITORS`，每个入选组 3 种）

1. `probe.py group` 按百分位看这组所有标题，找重复的打法（场景、人群、句式、封面套路）。
2. 写 `fmt(i)` 规则（正则，**判断顺序 = 优先级**，最后一个兜底），每种形式一句 `desc` + 一个内容标签（利益刺激 / 人设故事 / 实用攻略 / 效果展示 / 跨圈钩子 / 场景种草 / 品牌活动）。
3. 每种挑 3 个例子：**例子必须真的被 `fmt` 分到这个形式**（引擎不校验），优先百分位高的、有视频的、不同账号的。
4. 拼 27 张例子封面看一遍（`sheet.py --ids a,b,c,…`）再定稿 `desc`。
5. `transfer`（可迁移度底分）按形式给：小品牌一部手机能不能照着拍。官方活动、明星、吃播大胃王给低分。
6. 先跑一次引擎，看每组右上角（爆款 × 好迁移）有哪些形式、多少条，再写 `takeaway`：右上角的笔记有什么共同点，带数字。

## 4. 拆解（`TEARDOWNS`，每个入选组 1 条主例）

主例 = 最能代表打法、百分位高、**有视频或多图**、最好是小品牌自己的号（最好抄）。先 `probe.py note <id>` 看名次、数字、同账号其他笔记。
**必须看实物再写结构**：`frames.py <id>` 生成 `data/qa/frames/<id>.jpg`（视频每 4 秒一帧拼图 / 图文全部图片），用 Read 看，读字幕和画面。没看到的才放进 `inferred`（值必须是 `structure` 里某一步的 `t`）。

- `account`：名字、类型、库里几条（`inLib`）、一句观察；`matrix` 只在「同一活动多号铺量」时填，否则 `None`。
- `traffic.quant`：`lists: 'auto'`，`summary` 用真实数字（阅读、赞、藏 + 最好的几个榜单名次），`from` 写来源。
- `traffic.qual`：判断类型（推荐流 / 搜索长尾 / 投放加热 / 蒲公英合作 …）+ 理由（推广 / 蒲公英标记、出现在哪些搜索榜）；关键词表写每个词出现在 标题 / 封面 / 正文 / 话题 / 画面文字 / 视频字幕 的哪里；3 个推测长尾词。
- `money`：步骤链，没有数字不编数字，推断的写「（推断）」。
- `structure`：封面 / 标题 / 视频或图片，逐项写看到的；`why` 3 条。

## 5. 规律（`LAWS`，3 条）

1. `probe.py laws <slug> 'scene=…' 'person=…' 'price=…' 'origin=…' …` 一次试 6–9 个标题特征。
2. 选**差距大、能落到产品上**的 3 条，**至少 1 条反直觉**（尤其是和产品本能相反的：比如产品有产地故事，而带产地的标题爆款率更低）。样本 < 15 的特征不选。
3. `evidence.rx` 用同一个正则，`claim` 用 `{withHit}` `{withoutHit}` 占位，数字永远和数据一致。
4. 每条 3 个例子（来自入选组）+ `apply`（标题、封面、脚本、建议指标）+ `mock`（示意封面字，`<br>` 换行）。落地写给这个产品，具体到能直接拍；要用户补的数字写「（待确认）」。

## 交付前自查

- 引擎完整跑通（它会校验：没有空组、`COMPETITORS` 恰好是入选组、每个形式至少 1 条、`transfer` 覆盖所有形式、规律例子来自入选组；例子分错形式会打 warning，要修掉）。
- `picked` 的组都在右上角（◆）、没入选的都不在。
- 每个例子的形式对；所有例子 + 主例 + 规律例子都有 `srcVideo` 或 `srcImages`（`probe.py note` 看）。
- 文案里没有编出来的数字；推断都标了。
